# ADR 005: Референсный SUT архивирован — риск и план миграции

**Статус:** Accepted (риск принят, задокументирован)
**Дата:** 2026-04-16
**Автор:** Ситников Сергей (ssrjkk)

## Контекст

`mobius/screens/` — Screen Object Model, референс: Sauce Labs My Demo
App RN (`my-demo-app-rn`, package `com.saucelabs.mydemoapp.rn`).

## Проблема (обнаружено при аудите, не на этапе выбора SUT)

Реальная цепочка deprecation, подтверждённая через GitHub:

```
sample-app-mobile      (архивирован 8 мая 2024)
        ↓ "deprecated in favor of new React Native app"
my-demo-app-rn          (НАШ референс — ТОЖЕ архивирован 8 мая 2024)
        ↓ "deprecated in favor of new native apps"
my-demo-app-android      (актуальный, последний релиз v2.2.0)
my-demo-app-ios          (актуальный, последний релиз v2.2.2)
```

Дополнительно: `my-demo-app-ios` менял bundle ID между версиями
(`com.saucelabs.mydemoapp.ios` → `com.saucelabs.mydemo.app.ios`) —
конкретное доказательство что даже "актуальный" SUT требует
периодической ревалидации.

Также обнаружено (и исправлено отдельно): докстринги в `test_login.py`
и `test_ios_smoke.py` содержали НЕВЕРИФИЦИРОВАННЫЕ заявления о проверке
локаторов против конкретного APK — заявления были убраны, не факт.
Сеть в среде разработки не позволяет скачать реальный бинарник APK
(редирект на CDN вне allowlist) — локаторы основаны на публично
известных паттернах этого приложения, не на инспекции живого билда.

## Решение

Риск ПРИНЯТ на данный момент, не устранён, по следующим причинам:
1. `mobius/screens/` явно задокументирован в README как ПРИМЕР
   применения паттерна, а не единственный поддерживаемый способ
   использования framework — ядро (`mobius/utils/`,
   `mobius/driver/`) полностью SUT-agnostic (см. README
   "Архитектура: универсальное ядро + пример приложения").
2. Config-driven подход (ADR-002) снижает cost миграции на другой SUT —
   не требует переписывания Python классов, только новый YAML.

## Что НЕ сделано (открыто, для будущей работы)

- [ ] Миграция `mobius/screens/` на `my-demo-app-android`/
      `my-demo-app-ios` (актуальные, поддерживаемые SUT)
- [ ] Реальная верификация локаторов через `appium inspector` против
      живого билда — невозможно в текущей sandboxed среде разработки
      (нет Android SDK, нет эмулятора, сеть не даёт скачать APK)
- [ ] `apps/sauce_labs_demo.yaml` (ADR-002 config-driven пример) тоже
      ссылается на архивированное приложение — требует аналогичного
      обновления

## Последствия

- Любой инженер, берущий этот framework в реальный проект, ДОЛЖЕН
  первым делом заменить `mobius/screens/` под своё РЕАЛЬНОЕ
  приложение — сам SUT-пример не production-ready as-is.
- Урок процесса: при выборе референсного приложения для примера кода
  нужно проверять его maintenance status ДО, а не постфактум при
  аудите. Это не было сделано на этапе выбора `my-demo-app-rn`.
