Features

Structure for real device farms

The pieces a mobile suite actually needs: readable screen objects, pooled devices, reliable gestures and parallel runs.

Screen objects

Screens are modeled as objects with their own locators and actions — tests read like scenarios, not locator soup.

Device pooling

Devices are pooled and handed out to tests, so a run uses the whole farm instead of a single handset.

Gesture helpers

Swipes, scrolls and taps wrapped in reliable helpers — the fragile part of mobile UI is handled in one place.

Android + iOS

One suite targets both platforms through Appium 2.x drivers, sharing structure and fixtures.

Parallel execution

CI-ready infrastructure runs tests concurrently across pooled devices — wall-clock time drops as the farm grows.

No device needed to test

make test-all runs the suite's own checks without a device, so CI stays green even without hardware attached.

Quick start

Install and run

An editable install with test extras, then make targets for the suite and lint. No device required for the self-checks.

Python 3.12 Appium 2.x pytest Android iOS Make
terminal
$ git clone https://github.com/ssrjkk/mobius
$ cd mobius
$ pip install -e ".[test]"
$ make test-all   # no device required
$ make lint
