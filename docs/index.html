Mobile automation / Python + Appium

Один сценарий. Два устройства. Настоящий отчёт.

Mobius собирает экранные объекты, пул устройств, Appium-сессии и отчёты в один Python-пайплайн. Android и iOS используют одинаковую логику теста — меняются только capabilities.

Инструменты

Фреймворк держит весь прогон

Не набор разрозненных helpers, а связанные слои: от описания экрана до артефакта проверки.

Screen objects

Элементы, ожидания и действия живут в объекте экрана. Тест читает шаги сценария, а не цепочку локаторов.

mobius/screens/base_screen.py

Device pool

Устройства распределяются по worker-ам, порты не collide, занятое устройство возвращается в пул.

mobius/driver/device_pool.py

Gestures

Tap, swipe, long press и ввод текста проходят через W3C-команды с повторами и понятными ошибками.

mobius/utils/gestures.py

Parallel runs

Worker получает своё устройство и capabilities. Android и iOS не ждут друг друга.

DevicePool + worker routing

Appium session

Capabilities платформы превращаются в сессию, а тест занимается только сценарием.

mobius/driver/appium_driver.py

Report

Allure-шаги и pytest/junit сохраняют экран, действие и причину падения в артефактах.

reports/junit.xml
Пайплайн

От screen object до отчёта

Одинаковая последовательность для двух платформ. Меняется конфигурация, а не структура теста.

01

Screen object

Описываете экран и действия один раз.

mobius/screens/login_screen.py
02

Device pool

Worker занимает свободное устройство.

mobius/driver/device_pool.py
03

Appium session

Capabilities запускают нужный драйвер.

mobius/driver/capabilities.py
04

Report

Шаги и результат уходят в артефакты.

reports/junit.xml
